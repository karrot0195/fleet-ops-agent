**Input**: Feature specification from `/specs/001-nginx-fleet-upgrade/spec.md`

## Summary

Deliver an Agent Skill (`nginx-fleet-upgrade`) backed by a Python CLI that turns the
existing `PLAN.md` runbook into a reproducible, idempotent operator pipeline:

1. **Discover** the DigitalOcean fleet with `doctl`, reconcile `ip.txt`, and surface
   added/removed VMs.
2. **Survey** every VM read-only over SSH and assign exactly one verdict
   (`SKIP | UP-TO-DATE | UPGRADE | BLOCKED | UNREACHABLE`) with recorded evidence in
   `plan/{ip}.md`.
3. **Gate** the operator on one summary table; `execute` refuses to mutate a VM
   without an explicit approved IP set.
4. **Canary** the first approved VM, pause for an explicit proceed/stop decision, then
   roll out the remainder with bounded concurrency and exactly one retry round.
5. **Verify** each upgrade (config test, service, version, local HTTP/HTTPS) and flag
   config drift without auto-merging.
6. **Roll back** configuration from a verified backup when a VM fails, leaving the
   package at the new version.
7. **Report** per-VM outcomes and append one dated summary to `LOGS.md`.

The skill owns the conversational gates and procedure; the Python CLI owns evidence
collection, state, backups, execution, and rendering. All project-specific values
(Package, service, paths, probe URLs, allowed origins) come from configuration so the
same flow can later target another tool.

## Technical Context

**Language/Version**: Python 3.11+ (verified on host: Python 3.14.10). Standard library
only, plus PyYAML (already used by `server-deploy`; verified installed).

**Primary Dependencies**: OpenSSH client (`ssh`, `scp`), `doctl` 1.179+ (verified),
PyYAML. No `paramiko`, no Ansible, no `apt`/`nginx` on the operator host.

**Storage**: File-based — JSON run state, Markdown per-VM records, tarball config
backups. No database.

**Testing**: Standard-library `unittest` (pytest/ruff/mypy are not installed).
Fake `doctl`/`ssh`/`scp` executables and scenario fixtures for integration tests;
live read-only audit plus a gated canary drill for real validation.

**Target Platform**: Operator workstation Linux (Fedora host) driving Debian/Ubuntu
family VMs over SSH from `ip.txt`.

**Project Type**: Agent Skill + CLI operations tool (not a service or library).

**Performance Goals**: Bounded fan-out — survey and fleet execution run through a
thread pool capped at `execution.concurrency` (default 4); every SSH invocation has a
connect timeout and command timeout; no unbounded waits.

**Constraints**:
- No VM mutation before an explicit approval artifact; the CLI fails closed.
- Every mutation is preceded by a local, verified backup; rollback path always exists.
- Idempotent: re-audit changes nothing; re-execute on an upgraded VM yields
  `UP-TO-DATE`.
- Credentials, IP data, and backups never enter version control.
- apt-only upgrades; no `dist-upgrade`, package removal, `--fix-broken`, or auto-fix of
  BLOCKED VMs.

**Scale/Scope**: 12 VMs in the current inventory; one record per inventory VM; batches
of 4; one canary VM per run.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle / constraint | Gate requirement | Plan response | Status |
|---|---|---|---|
| Safety First (NON-NEGOTIABLE) | Local backup before every change + working rollback path | `execute` creates a remote tar, downloads it, verifies existence/size/checksum, and aborts that VM on failure. `rollback` restores the verified local archive after archiving the current config; package stays at the new version. | PASS |
| Explicit Confirmation Gates | No execution before the operator confirms the per-VM plan | `summary` emits the grouped table + eligible set; `execute` requires `--approve <ip,...> --yes` and validates the whole set before any mutation. `gate --decision proceed\|stop` records the canary decision; `execute --phase fleet` refuses without a recorded `proceed`. | PASS |
| Per-VM Traceability | Written `plan/{ip}.md` for every audited or modified VM | Every inventory IP gets a deterministic Markdown record rendered from state (verdict, evidence, execution, verification, drift, rollback). Records are per-IP and never merged. | PASS |
| Change Only What Is Needed | Updates justified by audit; minimal diffs | `UP-TO-DATE` and `SKIP` VMs are never touched. Upgrades use `--only-upgrade` with `--force-confold`; local config is preserved and upstream templates are staged as `*.dpkg-dist` flags only. No auto-merge. | PASS |
| Scripted and Idempotent | Reproducible, safe to re-run | All steps are CLI subcommands with deterministic outputs and atomic state writes; state-aware skip logic prevents duplicate work; re-runs converge. | PASS |
| Operational constraints | doctl inventory in `ip.txt`; parallel batches behind gates; credentials/IPs not committed | `discover` refreshes `ip.txt` from doctl; batching stays behind the approval gate; `.personal/`, `backups/` are already gitignored. **Remediation required**: `plan/` and `.fleet/` must be ignored and `ip.txt` must be untracked (`git rm --cached`) because it is currently committed. | PASS contingent on remediation task |
| Development workflow | Spec Kit flow; `LOGS.md` append-only | `report --log` appends one dated entry and never rewrites prior entries; idempotent per run. | PASS |

No gate violations require justification; Complexity Tracking is intentionally empty.

**Post-design re-check (after Phase 1)**: PASS. The contracts keep every mutation
behind an approval artifact plus a verified backup; state and records preserve per-VM
traceability; concurrency and retries are bounded; credentials and IP data stay out of
version control. The only outstanding item is repository hygiene (`ip.txt` tracked,
`plan/` and `.fleet/` not yet ignored), which is a task, not a design violation.
